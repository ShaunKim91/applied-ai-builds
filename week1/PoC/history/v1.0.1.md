# v1.0.1 — Follow-up review (security audit + script/docs polish)

**Date**: 2026-08-28 (follow-up session, after v1.0.0's initial build)
**Trigger**: The user asked two direct questions after reviewing the running app — (1) is model downloading genuinely CLI/shell-script driven end-to-end, and (2) does copying this project's code risk leaking the real OpenRouter API key — plus a request to re-audit all markdown documentation.

## What changed

### 1. Explicit CLI model-download script
Added `scripts/download_models.sh` — until now, model downloads only happened implicitly (triggered automatically by `app/main.py`'s startup bootstrap when `setup.sh`/`run.sh` start the container). This still fully satisfies the "CLI-driven, no manual UI steps" requirement, but there was no *explicit*, synchronous, per-model CLI command mirroring `download_data.sh`'s role for the two datasets. The new script downloads/verifies all 4 local models one at a time with real parameter-count output, tested live:
```
[1/4] WinKawaks/vit-tiny-patch16-224 ... 5,717,416 params
[2/4] intfloat/multilingual-e5-small ... 384-dim
[3/4] Qwen/Qwen2.5-0.5B-Instruct ... 494,032,768 params
[4/4] segmind/tiny-sd ... 530,099,307 params
```
`README.md` and `docs/guide.html` updated to document it alongside the other scripts.

### 2. Repository-root `.gitignore` added (real security gap closed)
A full re-audit of API-key handling (prompted by the user's question) found that while the `commerceiq` project itself never embeds the real OpenRouter key anywhere (verified by grepping the entire project tree, twice, with two independent methods — `command grep` and `find | xargs grep` — bypassing this shell's `.gitignore`-aware `grep` wrapper to be certain), the **top-level repository** (one level above the project folder) had **no root `.gitignore` at all**. If `git init` were ever run at that top level and everything committed, the real credential file `api_keys/openrouter.md` would have been swept in with it — a real, if not-yet-triggered, exposure risk.

**Fixed**: created a root-level `.gitignore` excluding `api_keys/` outright (plus standard OS/editor/Python/Node ignores as defense-in-depth for any project committed from the repo root instead of its own subfolder). Re-verified after the fix, with the ignore-aware grep wrapper deliberately bypassed:
```
$ command grep -rln "sk-or-v1" <repo-root>/
<repo-root>/api_keys/openrouter.md   <- only match, exactly as intended
```
Interesting side-effect noticed during this check: this shell's `grep` is wrapped to honor `.gitignore` patterns (`ugrep --ignore-files`) — the moment the new root `.gitignore` existed, an ordinary recursive `grep` calling api_keys/ from a script started auto-skipping it, an unplanned extra confirmation that the exclusion is effective, not just documented.

### 3. `debug/issue-07` — `run.sh` unnecessary port switch (real bug, found + fixed)
While bringing the app back up in this follow-up session (after a Docker Desktop restart), `run.sh` incorrectly treated its own already-running, already-healthy container as a "port conflict" and needlessly recreated it on a new port. Root cause and fix: see `../debug/issue-07-run-sh-unnecessary-port-switch.md`. `setup.sh` was intentionally left as-is (different, heavier-weight role by design).
