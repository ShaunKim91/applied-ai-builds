## Real bugs found and fixed this build (4 — see `../debug/`)

All found via direct manual multi-turn testing (first against a local Python process for fast
iteration, confirmed again in the real Docker container) — not synthesized, not assumed:

1. **Detached ORM instance across the SSE session boundary** — a `MemoryConflictLog` row created in
   one `SessionLocal()` session crashed when read again after that session closed. Fixed by extracting
   plain values before the session closes. (`debug/issue-01`)
2. **Structured memory never reached the reply prompt** — `MemoryFact` rows were extracted, persisted,
   and shown in the UI sidebar, but never actually injected into the chain that composes the reply, so
   a recall question outside the raw transcript window had nothing to draw on. Fixed by injecting a
   compact facts block into the system prompt every turn. (`debug/issue-02`)
3. **`ChatPromptValue` not subscriptable** — piping a real `ChatPromptTemplate` directly into the
   shared local-model `Runnable` (only exercised by the summarization chain) crashed the first time
   summarization actually ran. Fixed by normalizing the Runnable's input. (`debug/issue-03`)
4. **Callback-window preference never matched the fixed slot table** — a caller's "morning"/
   "afternoon" phrasing correctly auto-filled into a tool call, but the tool's own literal-substring
   match against `"...AM"`/`"...PM"`-stamped slots never actually fired. Fixed with an AM/PM-to-
   period classifier. (`debug/issue-04`)

Unlike Threshold (one bug, two manifestations, all in one mechanism) or Verity (three bugs, each in a
different subsystem), Throughline's four bugs cluster around genuinely new surface area for this
product family: real multi-session SQLAlchemy usage across a streaming boundary, a second independent
LCEL composition shape, and structured memory that has to actually reach the model. See
`../debug/README.md` for the full accounting, including why this count is honest rather than either
suspiciously low or high for this build's actual new-surface-area size.

## A real finding that is not a product bug

Local pre-Docker development (a Python virtual environment on this machine, used for fast iteration
before committing to a full container rebuild) produced a `RuntimeError: unsupported scalarType` and,
separately, a process-exit crash (`recursive_mutex lock failed`) — both traced to that environment's
`torch` build auto-detecting Apple Silicon's `mps` backend, a device this app's code never requests
and the real Docker deployment (Linux, the pinned CPU-only `torch==2.8.0+cpu` wheel) never has
available. Confirmed as a local-environment artifact, not a product defect: the real container ran the
same class of activity cleanly across three full clean rebuilds with zero occurrences. See
`../debug/README.md`.

## Corpus / data note

Throughline has no static seed corpus (see `projects/throughline/data/README.md`) — its tool set is a
small, fixed collection of local Python functions (account lookups, FAQ text, callback slots), all
deterministic and none requiring pre-indexing. The Chroma vector store indexes case summaries as they
are produced during actual use, not a pre-built corpus.
